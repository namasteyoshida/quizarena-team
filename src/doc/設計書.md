## 3-4 なぜuseStateではなくuseReducerか

クイズでは画面状態・現在の問題番号・スコア・回答履歴など複数の状態を同時に更新する必要がある。

useReducerを使用することで、状態遷移を1か所にまとめて管理でき、処理の流れが分かりやすく保守しやすい設計になるため採用した。

例えば「SELECT」1つのアクションで、statusがansweredに変わり、同時にスコアが加算され、answersに回答履歴が1件追加される。これらは「回答する」という1つの出来事から派生する変化なので、useStateを3つ4つ並べて個別に更新すると、更新順序や更新漏れのバグが起きやすい。useReducerなら「SELECTが来たら何が起きるか」を1つのreducer関数にまとめられるので、状態同士の整合性を保証しやすいと判断した

# 4. フックの採用理由

| フック | 使用箇所 | 目的・理由 |
|---------|----------|-----------|
| useReducer | QuizRunner | クイズの状態遷移・スコア・問題番号・回答履歴をまとめて管理するため |
| useEffect | Timer | タイマーを1秒ごとに更新し、setIntervalをクリーンアップするため |
| useRef | Timer | intervalIDを保持し、タイマーを停止・解除するため |
| useState | QuestionForm・App | 問題一覧や画面切替など単純な状態を管理するため |
| useContext（任意） | ThemeProvider | ライト・ダークテーマを全画面で共有するため |

## 4-1 Timerのクリーンアップ設計

TimerコンポーネントではuseEffectを使用してsetIntervalを開始する。

問題が切り替わったとき、回答したとき、画面を離れたときにはクリーンアップ関数でclearIntervalを実行し、不要なタイマーが残らないようにする。

依存配列は現在の問題や回答状態を監視し、変更時にタイマーを再生成する。

```ts
useEffect(() => {
  const id = setInterval(() => {
    // カウントダウン
  }, 1000);

  return () => clearInterval(id);
}, [currentQuestion, status]);
```
